# BTT Drops Desktop

The BTT drop checker (`https://www.firetickets.ai/btt/drops`) as a Windows app.

A browser tab can only alert you while it is open and allowed to play audio. This app polls the same
alert feed from the Electron **main** process, raises a real Windows notification, and plays an alert
sound you pick — window minimised, closed to the tray, or on another desktop.

## What it adds over the web page

| | |
|---|---|
| Native notifications | Windows toast per drop, with `Open on Ticketmaster` and `Mute 2h` buttons |
| Selectable alert sound | 14 purpose-built tones + every standard Windows notification sound |
| Priority nagging | A ⭐ event re-alerts on an interval until it is acknowledged |
| Tray resident | Close-to-tray, launch at startup, optional start-minimised |
| Auto-update | Silent, from the same Storage bucket the installer comes from |

Everything else — adding events, the picker map, targets, price tiers, never-sold, Recent Drops — is the
live web app in its own window, so there is nothing to keep in sync.

## Layout

```
main.js              window, tray, alert poller, notifications, sound routing, updates
preload.js           narrow bridge exposed to the HOSTED page (notify / acknowledged / openSettings)
settings-preload.js  wide bridge, LOCAL settings page only
player-preload.js    hidden audio window bridge
settings.html        sound picker + alert behaviour
player.html          hidden audio host (main can't play sound; the visible window is usually hidden)
offline.html         shown when firetickets.ai can't be reached
assets/sounds/*.wav  generated by scripts/make-sounds.mjs — never hand-edited
scripts/make-sounds.mjs   pure-Node PCM synth, one file per alert tone
scripts/make-icons.mjs    assets/icon.png -> multi-size icon.ico + tray.png
scripts/upload.js         publishes the installer + update feed to Supabase Storage
```

## Auth

No separate login. The window signs in to firetickets.ai normally and the poller uses
`session.defaultSession.fetch`, so `/api/btt/drops/popup` sees the same cookie. That endpoint only
answers the `michael` + BTT logins, which is exactly the audience for these alerts.

## Build & publish

```powershell
npm install
npm run sounds            # regenerate assets/sounds (only if make-sounds.mjs changed)
npm run icons             # regenerate icon.ico from assets/icon.png
npm run dist              # -> release/BTTDrops-Setup-<version>.exe

$env:SUPABASE_SERVICE_ROLE_KEY = '<service role key>'
npm run upload            # publish installer + latest.yml
```

`npm run release` is `sounds` + `dist` + `upload`.

**Bump `version` in package.json before publishing.** electron-updater compares it against
`latest.yml`; publishing the same version twice means installed copies never see the update.

The website reads `downloads/bttdrops-version.json` through `/api/btt/drops/desktop`, and the
`📥 DESKTOP APP` button on `/btt/drops` links to the stable `downloads/BTTDrops-Setup.exe`.

## Adding a sound

Add an entry to `SOUNDS` in `scripts/make-sounds.mjs`, add the matching row to `BUILT_IN` in `main.js`
(id, display name, one-line description), then `npm run sounds`. Keep them short (< 2.5s) and let the
normaliser handle loudness — every tone is levelled to the same peak so nothing in the picker is
startlingly louder than its neighbour.
